# Luminfield

简体中文 | [English](README.md)

Luminfield 是一款使用 Godot 4.7.1 .NET 与 C# 制作的原创双语农场生活
RPG 垂直切片。项目没有使用《星露谷物语》或其他商业游戏的素材、角色、
地图、文本、音乐及代码。

## 可玩内容

当前版本包含以下完整流程：

1. 与米菈交谈，领取星芽莓种子。
2. 开垦至少三块农田。
3. 种下并浇灌三株星芽莓。
4. 在小屋睡眠两次，让已浇水的作物成长。
5. 收获三株成熟的星芽莓。
6. 返回米菈处交付作物并完成试玩。

完成教程后可以继续经营：

- 在右侧的暮光商亭购买二十种原创作物的种子；芽辉季、雨幕季和星熟季各有
  四种限定作物，原有八种为兼容教程与旧存档继续支持跨季种植。
- 在农场商亭购买月梅树苗，种在家园开阔空地；成熟后反复采摘月梅，并用
  月梅、微光木和晶辉碎片制作辉巢，在成熟果树附近过夜酿出星蜜。
- 出售星芽莓、月辉根、云纹叶、微光豆、余烬铃、棱晶穗、露珠瓜、
  暮铃花、曦绫花、辉荚藤、雾歌薄荷、彗纹薯及价值更高的加工品，赚取微光币。
- 让三台固定加工机独立运作，并单独领取或原子领取全部已完成产物。
- 用收入购买更多种子，形成“种植 → 加工 → 出售 → 扩种”的持续循环。

原有 48×32 农场作为种植核心，纳入新的 64×64 初始主城区，并通过东侧月灯拱门
连接到 256×192 格的大世界。中央微光城扩建为 128×96 格枢纽，以更宽的城市路网
连接家园农场、低语林地、星落草甸、晶辉谷、月水湿地与星落遗迹；公共服务、
中央广场、商业街区和后期设施带各自成区，不再挤在同一个小中心。地图按 8×6 个
32×32 格区块加载，只保留玩家周围 3×3 个区块，因此镜头可以连续跨区移动，而
不必一次创建整张地图。本次为一次性拓扑重构，建立新的世界坐标基线，不迁移旧档
中的世界坐标。

大世界视觉沿用家园农场的完整主图逻辑：先生成四季全局构图、四季 64×64 初始区、
四季 128×96 中央城区，再为其余 11 个 64×64 世界分区分别生成高清母图，离线合成
为四张 4096×3072 连续季节主图。运行时只切换当前季节的单张主图，避免平铺地砖、
零散景观贴纸和分区接缝；程序化树木、晶体与采集物只保留承担交互所需的密度。
道路、水域、碰撞、资源、NPC、设施和存档状态仍由领域规则持有，不烘焙进背景。
中央城区进一步由四张重叠高清分区和一张中央广场精修图合成为原生 2048×1536
母图，不再把 1448×1086 单图放大到运行尺寸。

右上角迷你地图会随移动揭开已探索区块，隐藏未知区域，并标记已发现地标。
探索迷雾与区块记录会和常规存档一起保存。

## 星邮与关系奖励

- 家园小屋旁新增原创“星光邮箱”。选择第 1 格“手”，面向或邻接邮箱即可
  打开；有未读星邮时使用青绿色发光外观与真实对象轮廓，其他工具显示暖金色
  切手提示。没有未读内容时仍可查看，失败动作不消耗体力或物品。
- 第一次认识奈米后的次日会收到欢迎信。莉欧拉、塔维或奈米首次达到“可信
  朋友”后的次日，会各收到一封仅一次的奖励星邮，附件分别为晶辉碎片 ×2、
  微光木 ×4 和星芽莓种子 ×3。
- 哈尔登、玛维娅、西芙伦、多里克、凯尔、塞菈、艾洛温、维莎、奥林、伊瓦拉、
  布里尔、帕芙里和洛文则在各自第二段关系事件完成后的次日收到一次性奖励星邮；
  因此当前 16/16 名村民都有
  可实际领取的关系奖励，背包容量不足时不会丢失附件。
- 星光邮局面板会列出已送达邮件、未读状态、寄件人、送达日、双语正文、附件

  `Mail` 投影中。旧存档获得空邮箱，未知 ID 会过滤，读档与重复睡眠不会重复
  发放关系奖励。

## 工具与背包

8 格快捷栏和背包现在是两个层次：

- 第 1 格固定为“手”，用于收获成熟作物和查看地标。
- 星尘铲负责开垦农田，也能挖掘大世界里的晶体。
- 月纹柴刀负责砍伐可采集树木。
- 凝露壶最多携带 12 份水。
- 面向池塘、溪流或湿地水面使用汲水桶，可以补满凝露壶。
- 完整背包共有 24 格，按 `B` 或 `Tab` 打开；最上方 8 格就是快捷栏。

目标区会识别前方物件：青绿色轮廓表示可以按 `E` 执行，暖金色表示需要切换
工具，玫红色表示体力、水量、种子或背包容量不足。树、晶体、水面、作物、NPC、
门、商亭、加工机和床都会高亮真实对象范围，而不是只显示一个无含义的地面框。

树木产出微光木，晶簇产出晶辉碎片。采集后的节点会暂时从地图消失并变为
可通行；水晶隔 2 天、树木隔 7 天重新生长。旧存档中的永久移除节点会从读档日
开始进入安全的再生周期，`hoe` 也会自动迁移为新的固定工具顺序，不会丢失
已有种子和收成。

## 基础体验

新游戏会自动打开六张可跳过提示卡，覆盖当前任务、天气、出货、加工、委托和首次
探索；关闭后可按 `H`，或从暂停菜单选择“首日提示”，再次查看尚未跳过的卡片。
查询只读取 `GameSession`，不会提前修改任务、背包、货币、天气或存档状态。每张卡
同时给出“行动、入口、当前结果”三项闭环提示，并根据真实进度切换尚未开始、进行中
和完成状态。面板顶部还会始终显示任务、天气、出货、加工、委托和探索六项能力总览；
颜色直接派生同一份覆盖合同，跳过某张说明卡不会伪造完成状态或让整体进度消失。

确定性开局流程审计会从 `GameSession.NewGame()` 出发，连续经过任务、天气、委托、
耕种、出货、加工、探索和多次存档恢复检查。它证明前 90 分钟需求合同可由真实公开
动作走通，但不等同于真人连续游玩 90 分钟。加工品收取后的完成证据复用现有图鉴
发现记录，不新增第二套进度字段。米菈与小屋入口的固定目标提示也已归一到
`GameSession.PreviewSelectedTarget`，空手可用和错误工具提示不再由场景层复制。

Apple M3 / Metal 图形化代理实际运行已从标题页完整走到第 2 天：六卡引导、`H` 重开、
`O` 目标详情、`M`/`N` 小地图、米菈交谈、开垦、播种、浇水、入屋睡眠、夜间结算、
七卡晨报、保存返回标题和同日继续均通过。该记录保存在
`artifacts/screenshots/qa-01-runtime-route.md`；它不是 headless 或 Restore 完成态，
但仍不等同于真人 90 分钟。输入映射现在由集中合同注册并覆盖 Back、左摇杆按下、
十字键、A/B；引导和晨报覆盖层可用手柄 B / `ui_cancel` 关闭，物理手柄仍待实机。

HUD 常驻目标保持单行摘要；按 `O`、手柄 Back 或点击目标栏可打开完整目标详情。
小地图可折叠，并可在全部、地标与采集物标记间筛选。按 `G` 或从暂停菜单打开路线
引导后，可显式选择玩家当前区域能够抵达的目的地，或清除当前路线。六条真实道路合同
派生为 12 个只存在于当前会话的方向选项：家园与每个外围区域各提供一个去程/返程目的地，
村庄提供家园和五个外围区域。选中后 HUD 显示前进/回线方向与剩余距离，小地图标记下一
信标或终点，系统不会自动猜测目的地。首日提示、晨间简报和路线引导都可由手柄十字键与
A 到达。环境音会按
家园、村庄、荒野、天气、节庆和战斗上下文自动切换八类原创程序化循环，并以 0.45 秒
短交叉淡化过渡；15 类核心效果音配置共用同一合成入口。主音量、环境音量和效果音量
可在设置首屏
分别调节并即时保存。

`artifacts/audio/audio-01-preview/audio-01-acceptance-tour.wav` 提供一段 60.85 秒
的确定性技术试听，依次覆盖八类环境、0.45 秒淡化边界和 15 类核心音效，其中普通失败、
资源阻塞与工具错误使用可区分的程序化短音；响度舒适度、
疲劳感和切换听感仍需真人实听，不能由该技术产物代替。
自动音频质量门禁还会检查削波、RMS 响度、峰均比、低中高频能量、50ms 循环首尾
窗口、八类环境指纹距离和 0.45 秒交叉淡化连续性，并把指标写入同目录技术报告；
这些波形指标只能提前拦截明显技术缺陷，不能代替审美与疲劳感判断。

夜间总结结束后，或在 06:00 继续存档时，会以固定七卡顺序只读展示天气、邮件、
节庆、可触发角色事件、日常委托、周常委托与区域建议；可按 `J`，或从暂停菜单选择

目录；未知键保持普通失败，不会因包含 `missing`、`capacity` 或 `needs_tool` 等片段而被

均可用的真实暂停菜单布局。大世界
新增 57 个非交互导航信标，复用四季探索物件图集提示道路边缘、区域门槛与景观点
入口；六条家园/村庄到外围区域的关键路线把可通行无提示间距限制为 18 格，不改变
碰撞、路径、资源或存档。
`artifacts/screenshots/world-01-route-walk-audit.md` 会按真实 `WorldDefinition` 通行规则
重建六条完整四方向路线，证明合同可连续走通；它仍不能替代真人方向识别与迷路率测试。
`WorldNavigationRouteProgressPresenter` 进一步提供路线内最近格、下一信标、主方向、
回线方向、偏离距离和剩余步数的双向只读投影。返程选项复用同六条道路合同，并反转路径、
信标顺序、起终点、目的地区域、前进/回线方向、剩余步数与到达判定。路线选择只保存在

`WorldNavigationJourneyPlanner` 在纯 Core 层基于这 12 个方向选项生成跨区域多段行程：
同一区域为 0 段，村庄到任一区域为 1 段，家园或任一外围区域到其他外围区域经由
村庄稳定生成 2 段。路线选择层保存当前行程，并且只在玩家精确抵达当前段终点时自动推进

方向与偏离距离。带精确目标的晨报行程会额外增加一段只存在于当前会话的四方向接近路径：

或当前可通行谓词发现缓存格被阻挡时，会从玩家当前格重新规划到目标相邻可站格；若无法重建，
则暂不投影有效最后路径，等可通行条件变化后再恢复，避免把玩家引到已阻挡格。它仍然不写存档、
碰撞、探索或目标业务状态。开发验收可用
`--select-route-destination=<WorldBiome>` 显式启动纯区域多段路线。

## 开发试玩场景

开发启动参数按优先级集中注册在
[`PlaytestScenarioRegistry.cs`](src/Game/PlaytestScenarioRegistry.cs)。注册器
保持精确、区分大小写的匹配；同时提供多个已知参数时，优先选择注册顺序靠前的
场景；没有命中试玩参数时，游戏仍按正常流程停留在标题页。

`Main.CreatePlaytestScenarioRegistry()` 负责把每个场景 ID 绑定到对应的准备方法；
绑定集中在 [`Main.PlaytestBindings.cs`](src/Game/Main.PlaytestBindings.cs)。准备方法
按家园与设施、目标与收藏、活动与村庄、世界与基础验收拆分到四个
`Main.Playtests.*.cs` partial 文件。新增场景时，在注册器中补充 ID 与参数，在绑定
文件增加映射，并把准备方法放入对应领域文件。聚焦测试会锁定已知参数清单、唯一性、
优先级与正常回退行为。

运行时场景创建与切换集中在
[`Main.ScenePresentation.cs`](src/Game/Main.ScenePresentation.cs)，包括 HUD 建立、

## 本地工具链

项目固定使用以下版本：

- Godot 4.7.1 .NET

```bash
./scripts/open_editor_macos.command
```

该启动器会为 Godot 注入项目专用的 `DOTNET_ROOT`。不要直接从 Finder 双击
原始 `Godot_mono.app`，否则 Finder 不会继承本地 SDK 路径，编辑器会提示

```bash
export LUMINFIELD_TOOLS="$HOME/.codex/tools/luminfield"
export DOTNET_ROOT="$LUMINFIELD_TOOLS/dotnet"
export PATH="$DOTNET_ROOT:$PATH"

"$DOTNET_ROOT/dotnet" build
"$LUMINFIELD_TOOLS/godot/Godot_mono.app/Contents/MacOS/Godot" \
  --path "$(pwd)" --editor
```

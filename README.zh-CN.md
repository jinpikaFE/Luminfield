# Luminfield

简体中文 | [English](README.md)

Luminfield 是一款使用 Godot 4.7.1 .NET 与 C# 制作的原创双语农场生活
RPG 垂直切片。项目没有使用《星露谷物语》或其他商业游戏的素材、角色、
地图、文本、音乐及代码。

## 可玩内容

当前版本包含以下完整流程：

1. 与米菈交谈，领取星芽莓种子。
2. 开垦至少三块农田。
3. 种下并浇灌三株星芽莓。
4. 在小屋睡眠两次，让已浇水的作物成长。
5. 收获三株成熟的星芽莓。
6. 返回米菈处交付作物并完成试玩。

完成教程后可以继续经营：

- 在右侧的暮光商亭购买十二种原创作物的种子；新增四种只在芽辉季出售和
  播种，原有八种为兼容教程与旧存档继续支持跨季种植。
- 在农场商亭购买月梅树苗，种在家园开阔空地；成熟后反复采摘月梅，并用
  月梅、微光木和晶辉碎片制作辉巢，在成熟果树附近过夜酿出星蜜。
- 出售星芽莓、月辉根、云纹叶、微光豆、余烬铃、棱晶穗、露珠瓜、
  暮铃花、曦绫花、辉荚藤、雾歌薄荷、彗纹薯及价值更高的加工品，赚取微光币。
- 让三台固定加工机独立运作，并单独领取或原子领取全部已完成产物。
- 用收入购买更多种子，形成“种植 → 加工 → 出售 → 扩种”的持续循环。

原有 48×32 农场现已通过南侧发光石阶连接到 192×128 格的大世界。玩家可以
沿道路自由探索家园农场、低语林地、星落草甸、微光村、晶辉谷、月水湿地与
星落遗迹七个区域。地图按 32×32 格区块加载，只保留玩家周围 3×3 个区块，
因此镜头可以连续跨区移动，而不必一次创建整张地图。

右上角迷你地图会随移动揭开已探索区块，隐藏未知区域，并标记已发现地标。
探索迷雾与区块记录会和常规存档一起保存。

## 星邮与关系奖励

- 家园小屋旁新增原创“星光邮箱”。选择第 1 格“手”，面向或邻接邮箱即可
  打开；有未读星邮时使用青绿色发光外观与真实对象轮廓，其他工具显示暖金色
  切手提示。没有未读内容时仍可查看，失败动作不消耗体力或物品。
- 第一次认识奈米后的次日会收到欢迎信。莉欧拉、塔维或奈米首次达到“可信
  朋友”后的次日，会各收到一封仅一次的奖励星邮，附件分别为晶辉碎片 ×2、
  微光木 ×4 和星芽莓种子 ×3。
- 星光邮局面板会列出已送达邮件、未读状态、寄件人、送达日、双语正文、附件
  和领取结果。阅读与领取只通过 `GameSession`；背包已满时附件完整留在邮件中。
- 送达、已读和已领取状态以稳定邮件 ID 保存在 `schemaVersion: 1` 下新增的
  `Mail` 投影中。旧存档获得空邮箱，未知 ID 会过滤，读档与重复睡眠不会重复
  发放关系奖励。

## 工具与背包

8 格快捷栏和背包现在是两个层次：

- 第 1 格固定为“手”，用于收获成熟作物和查看地标。
- 星尘铲负责开垦农田，也能挖掘大世界里的晶体。
- 月纹柴刀负责砍伐可采集树木。
- 凝露壶最多携带 12 份水。
- 面向池塘、溪流或湿地水面使用汲水桶，可以补满凝露壶。
- 完整背包共有 24 格，按 `B` 或 `Tab` 打开；最上方 8 格就是快捷栏。

目标区会识别前方物件：青绿色轮廓表示可以按 `E` 执行，暖金色表示需要切换
工具，玫红色表示体力、水量、种子或背包容量不足。树、晶体、水面、作物、NPC、
门、商亭、加工机和床都会高亮真实对象范围，而不是只显示一个无含义的地面框。

树木产出微光木，晶簇产出晶辉碎片。采集后的节点会暂时从地图消失并变为
可通行；水晶隔 2 天、树木隔 7 天重新生长。旧存档中的永久移除节点会从读档日
开始进入安全的再生周期，`hoe` 也会自动迁移为新的固定工具顺序，不会丢失
已有种子和收成。

## 制作与星织储物箱

- 按 `C` 随时打开星织制作，也可以从背包顶部进入。
- 制作面板现在同时提供星壤肥、星织储物箱、月石道路、星木围栏、星光火炬和
  露滴洒水器六种配方；材料不足或背包已满时不会消耗任何物品。
- 1 份微光木与 1 枚晶辉碎片可以制作 2 袋星壤肥。
- 1 枚晶辉碎片制作 4 块月石道路；2 份微光木制作 4 段星木围栏；1 份
  微光木与 1 枚晶辉碎片制作 2 支星光火炬；4 份微光木与 3 枚晶辉碎片
  制作 1 台露滴洒水器。
- 月石道路、星木围栏和星光火炬放在种植区外的家园空地；道路可以通行，
  围栏和火炬会阻挡移动。露滴洒水器要放在未开垦的种植床格，睡眠结算前
  自动浇灌上、右、下、左四格已经开垦的土壤。
- 制作完成后，储物箱会自动移入可用快捷栏并选中。面向家园中的空闲目标格按
  `E` 放置；农田、固定设施、阻挡物和已有木箱所在格会明确显示不可放置原因。
- 切回第 1 格“手”，靠近木箱按 `E` 打开。每个木箱拥有 16 个独立储物格，
  可以在背包与木箱之间逐件存取种子、收成、加工品、采集材料和备用木箱。
- 木箱位置、开箱内容和背包状态都会随普通存档保存；旧存档会获得空的储物
  列表，不会清除已有进度。

## 作物品质与星壤肥

- 十二种作物现在都拥有普通、莹润、星辉三档品质。莹润售价约为普通的 1.5 倍，
  星辉约为 2.25 倍；品质使用稳定物品 ID，可在背包、储物箱、商亭与货箱中
  分别堆叠和结算。
- 选择星壤肥后，只有“已开垦、未播种、未施肥”的空土格会显示青绿色
  `E · 施用星壤肥`；未开垦、重复施肥或播种后的格子会给出对应原因，失败时
  不消耗肥料或体力。
- 星壤肥只影响当前一茬作物：收成保证至少为莹润品质，并有 20% 的稳定概率
  成为星辉品质。结果由作物、坐标和播种日决定，保存/读取不会重复刷新。
- 单次收获作物在收获后清除肥料。持续采收的辉荚藤在整株存续期间保留肥料与
  稳定品质结果，植株被移除时才清除。教程、每日交付、月井加工和星灯提交会
  把三档品质视为同一种作物；加工与提交优先消耗普通、再消耗莹润，尽量保留
  高价值星辉收成。

## 加工机与耕作技能

- 月井凝炼器、棱彩蜜渍缸与织星烘叶机是三台固定家园实体，分别保存配方、
  剩余夜数和完成态；云纹叶新增两夜加工链“云纹夜茶”。
- 统一面板可聚焦单台机器或领取全部完成产物。批量领取先完整模拟背包结果，
  任一产物放不下时，背包和三台机器都保持不变。
- 旧版单队列 `ProcessorSave` 只在没有合法现代机器记录时迁入月井凝炼器；
  旧版可合法放置木箱和装饰的格子继续保留，其内容不会因新机器丢失。
- 成功开垦、播种、浇水与收获统一获得耕作经验，等级为 0–5。达到 3 级后
  永久选择“守露人”（浇水少耗 1 点体力，最低 1 点）或“共鸣学者”
  （成功收获经验额外增加 50%）。

## 每日委托板

- 小屋与温室之间新增“星灯委托板”。切换到第 1 格“手”，靠近带青绿色轮廓
  的委托板按 `E` 打开；其他工具会提示切回手，失败操作不会消耗资源。
- 委托按天轮换，当前提供种植、采集和交付三类稳定模板。接取后，HUD 会同步
  显示标题和进度；未完成委托在睡眠跨日后过期，并刷新为新一天的任务。
- 种植只统计成功播下的目标作物，采集只统计真正放入背包的资源。交付会先
  检查背包数量，只有成功领取奖励时才一次性扣除物品并发放微光币。
- 委托日期、稳定定义 ID、接取状态、进度和领取状态都会随现有存档保存；
  旧存档或未知委托 ID 会安全获得当天的新委托，不会清除其他进度。

## 林地守望星灯

- 低语林地的旧守望灯已替换为可修复的“林地守望星灯”。切换到第 1 格“手”，
  靠近真实星灯轮廓后按 `E` 打开；其他工具只会提示切回手，不消耗体力或物品。
- 星灯包含三组可分批提交的星图节点：任意 3 种不同成熟作物、6 份微光木与
  2 份晶辉碎片，以及星芽莓蜜饯、月辉根药剂和星织储物箱各 1 件。
- 每种候选物只接受节点规定的数量。背包没有可用物品时不会扣除任何内容；
  已提交的部分进度会保留，三个节点只能触发一次完整修复。
- 完全修复后，地图星灯会从休眠外观切换为青绿星光状态，并永久把低语林地
  树木的再生周期从 7 天缩短为 4 天；其他区域的树木和水晶周期不变。
- 星灯发现状态、各节点的稳定 ID 与逐物品贡献、永久奖励都会保存在现有
  `schemaVersion: 1` 存档中。旧存档会安全获得空节点，未知或超量数据会在
  读取时归一化，不会错误解锁奖励或清除其他进度。

游戏内一天约等于现实四分钟，也可以在小屋的床上提前结束当天。

## 开发试玩场景

开发启动参数按优先级集中注册在
[`PlaytestScenarioRegistry.cs`](src/Game/PlaytestScenarioRegistry.cs)。注册器
保持精确、区分大小写的匹配；同时提供多个已知参数时，优先选择注册顺序靠前的
场景；没有命中试玩参数时，游戏仍按正常流程停留在标题页。

`Main.CreatePlaytestScenarioRegistry()` 负责把每个场景 ID 绑定到对应的准备方法。
新增场景时，在注册器中补充 ID 与参数，再在 `Main` 中增加准备方法绑定即可。
聚焦测试会锁定已知参数清单、唯一性、优先级与正常回退行为。

使用 `--playtest-liora-event-one`、`--playtest-liora-event-two`、
`--playtest-tavi-event-one` 与 `--playtest-tavi-event-two` 可以直接在月辉
档案馆或月石工坊打开对应的两阶段事件；这些参数保持既有注册顺序优先级，
并可配合 `--capture-playtest=<路径>` 进行确定性视觉验收。

使用 `--playtest-nemi-event-one` 与 `--playtest-nemi-event-two` 可在奈米普通日
14:00 的村庄路线直接打开两阶段友情事件；使用 `--playtest-starlight-post-door`、
`--playtest-starlight-post` 与 `--playtest-starlight-post-nemi` 可检查第五栋建筑
外门、只读路线分拣台和奈米室内工作位置；使用
`--playtest-starlight-post-wrong-tool` 可验证完整柜台轮廓显示暖金色工具不匹配状态。

使用 `--playtest-kael-event-one` 与 `--playtest-kael-event-two` 可在凯尔普通日
14:00 的真实村庄投影直接打开两阶段友情事件；使用
`--playtest-starfall-watch-door`、`--playtest-starfall-watch` 与
`--playtest-starfall-watch-kael` 可检查第六栋建筑外门、只读封印巡路台和
凯尔室内工作位置；使用 `--playtest-starfall-watch-wrong-tool` 可验证完整
巡路台轮廓显示暖金色工具不匹配状态。

使用 `--playtest-emporium-door`、`--playtest-emporium` 与
`--playtest-emporium-orin` 可分别检查暮光商铺外门、室内旅行货单架和奥林
室内互动，并同样支持确定性截图。

使用 `--playtest-village-rain-schedule` 可直接检查塞菈的小雨工坊对话；使用
`--playtest-village-rainveil-schedule` 可检查维莎在雨幕季第 1 天的路线与季节
HUD。两个入口都会先恢复显式当前天气，再从会话中的统一人物投影定位 NPC，
并支持确定性截图。

使用 `--playtest-npc-pathfinding` 可在 13:30 直接进入微光村，查看多名村民
处于两个日程锚点之间的格级移动；可配合 `--capture-playtest=<路径>` 做确定性
移动截图验收。

使用 `--playtest-gleamrise-crops` 可检查四种季节作物、辉荚藤持续采收与两种
确定性共鸣收成；使用 `--playtest-multi-processor` 可检查三台机器状态和原子
批量领取；使用 `--playtest-farming-specialization` 可检查耕作 HUD 与 3 级
永久专精面板。

使用 `--playtest-orchard-hives` 可检查成熟月梅树、可领取辉巢、果园快捷栏图标、
对象轮廓和确定性星蜜领取状态。
